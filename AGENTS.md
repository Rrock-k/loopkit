# Инструкция для AI-агентов

Ты работаешь с LoopKit-артефактами: HTML/проектами, которые умеют собирать фидбэк прямо внутри интерфейса.

## Когда создаёшь новый артефакт

Сделай артефакт самодостаточным и совместимым с LoopKit:

1. Добавь metadata:
   - `artifact_id`
   - `artifact_version`
   - `title`
2. Добавь `DECISIONS` — короткий список устойчивых решений.
3. Разметь важные элементы через `data-loop-id`.
4. Используй смысловые ID, а не координаты:
   - хорошо: `game.start-screen.play-button`
   - плохо: `div-12`
5. Подключи `loopkit.js` или встроь runtime inline.
6. Не добавляй сложную инфраструктуру без необходимости.

## Когда делаешь новую версию по feedback bundle

1. Проверь, что `feedback_bundle.artifact_version` совпадает с текущим HTML.
2. Прочитай `DECISIONS` и не нарушай их.
3. Обработай каждый feedback item.
4. Если фидбэк конфликтует с другим фидбэком или `DECISIONS`, не выбирай молча — попроси решение пользователя.
5. Создай новую версию артефакта.
6. Увеличь `artifact_version`.
7. В ответе перечисли, что сделано по каждому пункту bundle.
8. Не переноси старый feedback bundle в новую версию.

## Правило одной итерации

Feedback bundle живёт только одну итерацию.

```text
HTML v1 + feedback bundle v1 → HTML v2
```

После создания v2 bundle v1 считается использованным и больше не применяется. Если проблема осталась, пользователь оставит новый фидбэк уже в v2.

## Что нельзя делать

- Не удаляй `data-loop-id` без причины.
- Не применяй bundle к другой версии HTML.
- Не игнорируй feedback items молча.
- Не превращай LoopKit в баг-трекер или систему вечной истории.
- Не нарушай `DECISIONS` без явного подтверждения пользователя.
